Call Queue Manager — Behaviour Guide

How the bulk audit & update tool reads your sheet and applies changes to RingCentral call queues.

1. Audit & upload flow 2. Blank columns are ignored 3. Voicemail notification styles 4. Advanced mode & why it's needed 5. Per-type notification addresses 6. Manager queues & the Convert option 7. Overwriting members 8. Preview, skips & results

1. Audit & upload flow

The tool works in two halves that share one spreadsheet layout:

  • Audit & Export — select queues and download their current configuration into the master template.
  • Upload & Process — edit that sheet, then Preview (a dry run that writes nothing) and Confirm & Sync (applies the changes).

Always Preview first — it shows exactly what would change, per queue, with no risk.

2. Blank columns are ignored

You never have to fill the whole sheet. A blank cell means "leave this setting exactly as it is." Only columns you fill in are considered, and only queues whose values differ are written.

3. Voicemail notification styles

The Voicemail Notifications column accepts:

ValueMeaning
OffNo voicemail email notification.
Notify by EmailEmail on, no attachment.
Notify & AttachEmail on, voicemail attached.
Notify Attach & ReadEmail on, attached, and marked read once emailed.

Voicemail to Text (On/Off) controls transcription independently.

4. Advanced mode & why it's needed

RingCentral notification settings have two modes:

  • Basic — a single on/off "By email" tick per notification type, one shared recipient. No attach or mark-as-read options.
  • Advanced — per-type recipients, plus Include attachment and Mark as read.
Attach, Mark-as-read, and per-type addresses only exist in advanced mode. So whenever your sheet asks for Notify & Attach, Notify Attach & Read, or a per-type email address, the tool automatically switches that queue to advanced mode. A VM Advanced Mode row appears in the preview when this happens. Plain Notify by Email and Off stay on basic mode.

When a queue is switched to advanced mode, its existing notification address is cascaded across every notification type that is on, because advanced mode requires each enabled type to carry its own recipient. Each type's on/off state is left as-is unless your sheet changes it.

Address priority for each type, in advanced mode:

  • 1. That type's own address column, if filled.
  • 2. Otherwise the cascade address — the Voicemail Notifications Email if you supplied one, else the queue's existing notification address.

Supplying any per-type address puts the queue into advanced mode (basic mode can only hold one shared address).

6. Manager queues & the Convert option

There are two kinds of queue notification setup, and they behave differently:

TypeRecipientDefault behaviour
Specified Emails
(incl. a dummy "Manager Email" address set via API)		 A real, editable address is stored on the notification settings. Processed as normal.
User Manager Delivered to a real user Manager by reference — no editable address is stored. Skipped by default.
The Manager Email field on the queue's General tab is not the notification recipient. What matters is the Notifications → Send email notifications to setting. If it points to a real user Manager, there's no editable address to work with — and advanced mode won't accept a manager reference — so the queue is skipped and reported.

The "Convert manager-notification queues" checkbox

  • Unticked (default): user-Manager queues are skipped and listed as Skipped.
  • Ticked: for those queues the tool unticks the Manager, switches to advanced mode, and sets the specified email(s) from your sheet as the recipient(s).
Conversion needs an address to switch to. If the checkbox is ticked but the sheet provides no email (Voicemail / per-type / Queue Email) for that queue, it is still skipped — there is nothing to convert it to.

7. Overwriting members

  • Off (default): members listed in a row are added; nobody is removed.
  • On: the queue is made to match the sheet exactly — anyone not listed is removed.
  • A blank Members (Ext) column is never changed either way.

8. Preview, skips & results

  • Preview writes nothing — it lists every proposed change as Pending.
  • Skipped rows (neutral badge) explain why a queue was left untouched — most often a user-Manager notification recipient.
  • After a real sync, rows show Applied, and a results spreadsheet can be downloaded.

This page reflects the current tool behaviour. If a queue behaves unexpectedly, run a Preview first and check the Skipped/So reason shown for that extension.
